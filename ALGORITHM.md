# Алгоритм обработки данных и обучения (RNN)

## 1. Загрузка и первичный парсинг CSV
- Пользовательский CSV читается целиком в браузере, разделитель автоопределяется, заголовки приводятся к trim-форме. Пустые строки/пропуски фильтруются, а обязательные столбцы (включая метку `y` и числовые/категориальные базовые поля) проверяются на наличие, иначе выдаётся ошибка загрузки. Лишние колонки с утечками (`Tournament`, `Rank_1/2`, `Pts_1/2`, `Odd_1/2`, `Winner`, `Score` и др.) удаляются сразу после парсинга, а по каждой строке фиксируются метаданные игрока/даты/категорий для дальнейшей агрегации. Это выполняется в `DataLoader.loadCSVText`. 

## 2. Выбор фичей и нормализация для последовательностей
- При работе в последовательностном режиме (`modelType` = RNN) используется строгий список из 16 числовых engineered‑признаков (`rank_diff`, `pts_diff`, `odd_diff`, `h2h_advantage`, `last_winner`, `surface_winrate_adv`, win‑rate/streak/fatigue блок, динамический `surface_trend`, `year`). Устаревшие surface winrate‑по‑покрытию колонки удалены. Список валидируется по заголовкам, отсутствие признака вызывает ошибку.
- Нормализация (mean/std) вычисляется только на тренировочной выборке и применяется к тренировочным, тестовым и полным строкам до сборки последовательностей. Значения `year` фиксируются на сценарный год при нормализации. Все ненормальные числа заменяются нулями, тем самым предотвращаются NaN.

## 3. Формирование временных рядов
- `surface_trend` пересчитывается в `DataLoader`: для каждого игрока и покрытия берутся предыдущие матчи на этом покрытии, считается разница краткосрочного win rate (окно 5) и долгосрочного (окно 15); при отсутствии истории — 0. Значения клиппируются в [-1, 1] и подставляются в строки перед нормализацией.
- Функция `buildSequences` группирует матчи по игрокам, сортирует их по времени и для каждого матча берёт предшествующие `seqLen` встреч. Если матчей меньше окна, слева добавляется паддинг из нулевых векторов. Каждый шаг временного ряда собирается строго в порядке `featureList`, а любые нечисловые значения в ноль. На выходе: `X` (массив [samples, seqLen, numFeatures]), `y` (целевые метки), метаданные (карта индексов признаков, информация о сэмплах) и статистика (доля паддинга, наличие NaN).

## 4. Превращение последовательностей в тензоры и сохранение метаданных
- Нормализованные последовательности превращаются в `tf.tensor3d` и `tf.tensor1d` для train/test, а метаданные содержат тип модели, порядок фичей, карту индексов, длину окна, статистику паддинга и параметры нормализации. Это обеспечивает единообразное обучение/инференс и корректное восстановление после сохранения модели. 

## 5. Архитектура и обучение RNN
- Модель строится через `buildRNNModel`: SimpleRNN → Dropout → Dense(ReLU) → Dense(sigmoid). Гиперпараметры (units/denseUnits/dropout/learning rate) имеют безопасные дефолты. После компиляции с Adam + `binaryCrossentropy` запуск `fit` использует 3D входы и пишет логи по эпохам; успешное завершение включает метрики и возможность сохранить/оценить модель. 

## 6. Инференс для выбранного игрока
- Для прогноза формируется свежая последовательность через `buildSequenceInputForMatch`: по имени игрока берутся его последние `seqLen` матчей, нормализуются теми же mean/std и дополняются паддингом слева. Результат возвращается как `tensor3d` формы `[1, seqLen, numFeatures]` плюс сводка (дата последнего матча, наличие паддинга). Тензор подаётся в RNN, а предсказанная вероятность интерпретируется в UI как шансы победы выбранного игрока.
